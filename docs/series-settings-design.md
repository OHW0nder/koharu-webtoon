# 漫画级设置：三项的归口

本文是漫画层全部设置项的**入口与存储归口**。三项设置共用章节管理页的同一个设置区，但读取时机与持久化位置各不相同——把它们混为一谈会导致存储选错。

各项的完整判定在各自的文档里，本文不重复：

| 设置 | 详情 |
| --- | --- |
| 条漫广告高度 | `docs/reference/webtoon-ad-bands-design.md` |
| 翻译指导与术语表 | `docs/series-translation-assets-audit.md`（注入）、`docs/reference/koharu-glossary-design.md`（派生与过滤） |

三层结构本身的决策见 `docs/series-layer-design.md`；扩展的形态约束见 `docs/extending-koharu.md`。

## 1. 三项设置

| 设置 | 内容 | 读取时机 | 持久化位置 |
| --- | --- | --- | --- |
| **广告高度** | 首条与尾条的像素高度 | **导入时**，每张长图各读一次 | 漫画索引 |
| **翻译指导** | 手写散文：本作的风格约定 | 渲染注入内容时 | 漫画索引 |
| **术语表** | 结构化词条：原文、译文、类别、备注 | 渲染注入内容时，先按待译内容过滤 | 独立文件 |

### 1.1 广告高度为什么不能存在章项目上

它在导入动作发生时读取，而**首次导入时章项目还不存在**。

由此得到一条可复用的判定规则：

> 如果一个值需要在某个动作发生时读取，而这个动作发生前承载它的实体还不存在，那么这个值不能存在那个实体上。

### 1.2 术语表为什么不放在索引里

索引是编排数据，会被频繁读、小幅写。术语表可能有数百条词条，每条都可能是一次编辑。放进索引会让**改一个词条就要重写整个编排文件**，并且人类可读性很差——而术语表恰恰是最需要人工编辑与版本管理的资产。

因此术语表存漫画目录下的独立文件，索引里只留一个文件名引用。

翻译指导是单段散文、每次改动量小，放索引合适。

### 1.3 角色卡不做

原方案里的第四项已决定不做。切片无法保证把说话人完整地留在同一页——气泡的尖尾可能落在上一页，人脸可能被刀口分开。说话人归属本身不可靠，描述「谁用什么语气说话」的资料没有可靠锚点。

术语表不受影响：词条靠**文本匹配**定位，出现在待译片段里就注入，与说话人归属无关。这个区分是两项去留不同的原因。

## 2. 统一入口

**章节管理页的设置区**，三项并列。不在设置页——设置页承载全局配置，而这三项都是作品级的，放进去会造成作用域混淆。

### 2.1 形态

| 分区 | 控件 |
| --- | --- |
| 条漫广告 | 首条高度、尾条高度两个数值输入，各带清除；实时显示「本作品 N 章适用」 |
| 翻译指导 | 多行文本域 |
| 术语表 | 词条列表，每行原文、译文、类别、启用、来源标记；添加、导入、导出 |

不提供滑块：条漫动辄上万像素，滑块刻度精度不够，而且用户是照着画面里的实际位置输入的，滑块给不出「对，就是这里」的确认感。

### 2.2 章节管理页的连带简化

因为设置只有一份、不存在逐章覆盖，**「某章的广告设置是什么」这种需要查询的状态不存在**。章节管理页因此不需要为设置发起任何按章的查询。

### 2.3 导入对话框只承担首次创建

导入对话框不承担管理职责，只在漫画尚不存在时无处可存：

| 场景 | 广告高度来源 |
| --- | --- |
| 新建漫画并首次批量导入 | 对话框给出该值，写入索引 |
| 新增章节，未改动 | 沿用设置区里的值 |
| 新增章节，改动或关闭开关 | 用本次对话框的值；**不写回**索引 |

改动索引里的值**只影响之后的导入**。已导入章节的切片已经在库里，重新裁剪意味着删页重建，会丢弃已完成的识别与翻译。

技术上可回溯——导入时切片组件记录的溯源引用指向**完整未裁剪的原图**，源图字节仍在项目里。但本期不提供该动作。

## 3. 风险分级

| 内容 | 触碰官方 | 说明 |
| --- | --- | --- |
| 漫画索引新增字段 | 否 | 旁挂文件 |
| 术语表独立文件读写 | 否 | 旁挂文件 |
| 导入流程中的广告带裁剪 | 否 | 只改本仓库的导入函数 |
| 渲染注入内容 | 否 | 纯函数 |
| 作用域管线接线 | 否 | 公开 API 组合 |
| 章节管理页设置区 | 否 | 前端独立 |
| 场景内核 / 翻译层 / 流水线 | 否 | 零改动 |

全部为绿色，**没有黄色改动**。
