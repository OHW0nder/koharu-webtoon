# 条漫广告带：导入时裁剪

本文记录「设定首尾广告高度，导入时裁掉」的设计判定。

形态约束见 `docs/extending-koharu.md`。相邻设计见 `docs/series-layer-design.md`（漫画/章/页三层）。

---

## 1. 目标与非目标

**目标**：条漫的下载产物是纵向长图，一章的首图顶部与末图底部各有一段固定高度的站点广告。这些区域里的文字不需要翻译，检测与识别它们纯属浪费。设定首尾广告高度后，导入时把这两段从源图裁掉，再走正常的切片与流水线。

**两端的归属**：广告带描述的是**整章**，不是每一张源图。一章由若干张长图组成时，只有首图承担顶部那一条、末图承担底部那一条，中间的图两侧都是正文。若每张图都减去两条，首图的尾部和末图的头部这两段正文会被一起削掉。

**非目标**：

- 不保留广告像素。裁掉的部分直接丢弃，导出结果不含首尾广告。
- 不做内容识别。广告高度由用户给出，引擎不判断哪一段是广告。
- 不影响已导入的章节。改动设置只对之后的导入生效。
- 不在批处理阶段跳过页面。广告在导入时就不存在了，批处理阶段无需任何特殊处理。

---

## 2. 事实基础

### 2.1 广告像素在导入时裁掉，不是在批处理时跳过

两者都能达到「不翻译广告」，但差别很大：

| | 批处理时跳过整页 | 导入时裁掉（采用） |
| --- | --- | --- |
| 部分落在广告里的切片 | 广告文字仍被识别与翻译 | **不存在这种切片** |
| 切点搜索 | 广告区可能产生「看起来平坦」的候选切点，浪费搜索窗口 | 广告区已移除，窗口全给正文 |
| 省下的页数 | 按切片边界向上取整，不精确 | 精确等于「广告高 ÷ 平均页高」 |
| 项目里的存储 | 广告页仍占空间 | 广告不在项目里 |
| 批处理逻辑 | 需要按过滤后的页列表运行 | **无需任何改动** |

采用的方案让批处理路径保持原样，这是它最大的好处。

### 2.2 切片器不感知气泡，广告带不在它的考虑范围内

切片判据是逐行亮度统计：整行亮度极差小于阈值、且均值偏亮或偏暗的行才算「留白带」，切点优先落在留白带中心。气泡内部的白色只在气泡宽度范围内均匀，跨过气泡边界的行极差很大，因此不算留白。

**切片器对气泡没有任何感知。** 这与本功能无关，但决定了「裁掉广告」不能依赖切片器帮忙——广告必须在切片之前处理掉。

### 2.3 裁剪可以完全在本地 crate 内完成

切割规划是纯函数，接受「图像高宽 + 逐行剖面」。因此裁剪不需要真的裁图像：

1. 对**完整**图像算行剖面
2. 把剖面按广告高度裁成中段
3. 用中段高度与中段剖面调用规划器
4. 规划器产出的偏移是相对中段的，**统一加上起始偏移**，就得到相对原图的绝对偏移
5. 按绝对偏移从完整图像裁出切片

第 5 步从完整图像裁，所以切片像素与原图逐像素对应，只是起始位置被推后了。

这个做法不修改规划器所在的 crate，只改编排导入流程的那一个函数。

## 3. 存储

### 3.1 存在漫画索引，不存在章项目上

广告高度是**漫画级**的设定，理由是它的读取时机：

- 它必须在**导入动作发生时**被读取
- 而首次导入时，章项目还不存在

一条判定规则：**如果一个值需要在某个动作发生时读取，而这个动作发生前承载它的实体还不存在，那么这个值不能存在那个实体上。** 存在漫画索引里，导入命令按项目名反查所属漫画即可。

这也带来一个简化：设置只有一份，不存在「逐章覆盖」，因此**没有「某章的广告设置是什么」这种需要查询的状态**。章节管理页不需要为此发起任何请求。

### 3.2 与术语表资料的关系

翻译指导与术语表也存漫画级，但它们是**作品资料**，在渲染注入内容时读取。广告设定不同，它是**导入参数**，在导入时读取。两者同属漫画级但读取时机不同，不要混在一处。

三者的存储归口与统一管理入口见 `docs/series-settings-design.md`。

### 3.3 命名空间与不变量

若将来需要为单章提供覆盖，它会是一个章项目上的自定义组件。**本期不提供**，因为导入对话框已经允许逐次调整。

## 4. 生效时机

三个场景，一个值：

| 场景 | 广告高度的来源 |
| --- | --- |
| 新建漫画并首次批量导入 | 导入对话框里由用户给出，同时写入漫画索引 |
| 为已有漫画新增章节，**用户未改动** | 沿用漫画索引里的值 |
| 为已有漫画新增章节，**用户改动或关闭开关** | 使用本次对话框里的值；**不写回**漫画索引 |

**改动索引里的值只影响之后的导入。** 已导入的章节不会被追溯处理——它们的切片已经在库里，重新裁剪意味着删页重建，会丢弃已完成的识别与翻译。

### 4.1 技术上可回溯，但默认不做

源图的**完整未裁剪字节**保存在项目里：切片组件的溯源字段记录了一个内容寻址的 blob 引用，导入时创建的临时载体页在插完切片后被删除，但该 blob 因被切片指名而不会被垃圾回收。注释里写明了这就是为了「可以按新的边界重新切割」。

所以「重新裁剪某个已导入章节」在数据上可行：读出源图 blob、重新规划、删除旧页、按新边界重建。

**本期不做这个动作。** 它需要一个会丢弃已有工作的确认流程，且大多数情况下用户不会需要。

### 4.2 入口在章节管理页的设置区

广告高度与翻译指导、术语表**共用章节管理页的同一个设置区**，不单独开一个导入选项面板。三项都是漫画级设置，用户在一个地方管理。

读取时机的差异由导入命令自己处理，不影响入口的集中：

| 场景 | 广告高度的来源 |
| --- | --- |
| 新建漫画并首次批量导入 | 漫画尚不存在，导入对话框给出该值，同时写入索引。之后从设置区管理 |
| 为已有漫画新增章节，**用户未改动** | 沿用设置区里的值 |
| 为已有漫画新增章节，**用户改动或关闭开关** | 使用本次对话框里的值；**不写回**索引 |

因此导入对话框只需要两处交互：首次导入时的高度字段，以及后续导入时的「沿用本漫画设置」开关。**它不承担管理职责，只是首次创建时无处可存。**

**改动索引里的值只影响之后的导入。** 已导入的章节不会被追溯处理——它们的切片已经在库里，重新裁剪意味着删页重建，会丢弃已完成的识别与翻译。

## 5. 边界与降级

### 5.1 值本身

首条与尾条各自可以为 0，表示那一端没有广告。两个都为 0 等价于关闭裁剪。

### 5.2 必须校验的情况

设源图高为 `H`，首条为 `head`，尾条为 `tail`，中段高为 `M = H - head - tail`。`H` 是**实际承担那一条广告带的那张图**的高：中间那些图两端都是 0，`M` 就是整图高。

| 条件 | 处理 |
| --- | --- |
| `M <= 0` | 非法，广告高度之和超过图高 |
| `M < min_height` | 中段切不出合法页，见下 |
| `head` 或 `tail` 为负 | 非法 |

### 5.3 单张图不满足时不中断整批

一章可能有几十张长图，其中某一张的实际尺寸可能小于设定值之和。**这种情况应当跳过该张的裁剪、保留原图导入，并明确回报**，而不是让整批导入失败。

理由：一次批量导入涉及几十个文件，任何一个文件的问题导致全部失败，代价远大于收益。用户需要的是「第 3 张没裁，因为广告高度设置对它太大了」这样一条可执行的提示，而不是一个失败对话框。

裁剪只对**会被切成多页**的图生效。不满足切片条件的普通页本来就不切，对它裁剪没有意义。

### 5.4 批量导入后的回报

导入完成时汇总：本批共多少张图被裁剪、多少张因设置过大而跳过。跳过是结果的一部分，不是错误。

## 6. 对既有设计的影响

### 6.1 批处理路径不变

原先设想在批量处理时传入过滤后的页列表。**这个需求消失了**——广告页在导入时就不存在，项目里没有需要过滤的页。批量命令、进度汇报、章状态全部保持原样。

### 6.2 切片参数与本功能解耦

裁剪发生在切片之前，因此不影响切片高度的取值。切片高度的选择有独立的三个约束（检测横向分辨率、页数与请求开销、切到气泡的概率），本功能不参与那个权衡。

### 6.3 导出结果不含首尾广告

这是「裁掉」的直接后果，也是本功能接受的取舍。导出的文件是正文，不含站点广告。

| 内容 | 触碰官方 | 说明 |

| 漫画索引新增两个高度字段 | 否 | 旁挂文件 |
| 导入流程中的剖面裁剪与偏移还原 | 否 | 只改本仓库的导入函数 |
| 导入对话框的两个字段与一个开关 | 否 | 前端独立 |
| 切割规划器 | 否 | 传入裁剪后的高度，不改参数结构 |
| 场景内核 / 翻译层 | 否 | 零改动 |

全部为绿色。**没有黄色改动。**

## 8. 已知限制

1. **不保留广告像素**，导出结果不含首尾广告。
2. **值改动不追溯已导入的章节。** 技术上可回溯（源图完整保留），本期不提供该动作。
3. **不做内容识别。** 同一源的广告高度稳定是用户的经验判断，引擎不验证。换了下载源导致广告高度变化时，需要用户自己改。
4. **逐次导入可逐次覆盖**，但覆盖不写回漫画索引，因此下次新增章节又会回到继承值。如果某几章确实需要不同处理，用户需要每次导入时调整。
5. **条漫专用。** 页漫不提供该设置，界面不出现该入口；判定依据是章条目记录的源形态，不是运行时猜测。
