## Supported formats

| Purpose             | Format                              |
| ------------------- | ----------------------------------- |
| Import              | PNG, JPEG, WebP, CBZ, ZIP, RAR, PDF |
| Reader archive      | CBZ (JPEG inside)                   |
| Lossless archive    | ZIP or directory, PNG               |
| Layered interchange | PSD                                 |
| Chapter project     | directory of the application's own choosing |

## Project data

Chapters live under a library folder, one directory per series with one directory per chapter inside it:

```text
<library>/
  Demo Title/
    series.json
    Chapter 22/
      state-a.khr
      state-b.khr
      blobs/
      project.lock
```

The library folder defaults to `Documents/Koharu` and can be pointed elsewhere in **Settings → Library**. The change takes effect after a restart, and Koharu never moves existing series for you: move or delete them first, or the change is refused.

Each chapter directory contains alternating durable state files, a lock file while the chapter is open, and content-addressed blobs for source images, generated artwork, and authored raster edits. Unreferenced blobs are not removed automatically, so a heavily edited chapter can grow over time.

<Warning>
  Do not change internal chapter files while the chapter is open. Deleting a chapter or a series from the app permanently removes its directory.
</Warning>

## Settings and credentials

Non-secret typed settings live in `~/.koharu/config.toml`, with sections for the pipeline (including translation), providers, typesetting, Agent, and HTTP timeouts. Missing settings use defaults. Invalid manual edits can prevent initialization; use the Settings UI.

Provider credentials use the operating system's secure credential service. A project backup does not include provider keys or the Agent account session.

## Runtime and model cache

On macOS and Linux, packages are stored at `<cache>/koharu/packages/` under the operating system cache directory. On Windows, they are stored in the `store` directory inside Koharu's installation directory. This data is replaceable: removing it while Koharu is closed causes the required packages to download again.

Never remove a package while the desktop process may still have a native library loaded.

## Back up safely

<Steps>
  <Step title='Close the project'>Finish current work before copying its files.</Step>
  <Step title='Copy the entire directory'>
    Keep the state files and blobs together. A PSD export is not a project backup.
  </Step>
  <Step title='Save settings separately'>
    Copy `config.toml` if needed. Reconfigure credentials through Koharu on the restored machine.
  </Step>
</Steps>
